# 5. 工具调用和函数调用是什么？有什么区别？

## 知识点讲解

### 1. 核心概念

这两个词经常被混用，但它们的层次是不一样的。

**工具调用（Tool Calling）** 是广义概念——Agent 通过任何方式去调用外部能力：搜索引擎、计算器、数据库、邮件接口……不管用什么机制把调用发出去，都叫工具调用。

**函数调用（Function Calling）** 是狭义实现——OpenAI 和 Anthropic 等厂商在 LLM 层原生支持的一种结构化输出机制。模型在生成文本的同时，能直接输出"我要调用哪个函数、参数是什么"，由框架侧自动执行，再把结果喂回模型。

说白了：Function Calling 是实现 Tool Calling 的一种方式，而且是目前最可靠的方式。

两者的核心差异：

| 维度 | Tool Calling（广义） | Function Calling（原生） |
| --- | --- | --- |
| 调用发起方式 | Prompt 解析、JSON 提取等 | 模型原生输出结构化调用 |
| 可靠性 | 中等（依赖文本解析） | 高（结构化、有 schema 约束） |
| 模型要求 | 任意模型 | 需要模型支持 |
| 参数格式 | 自定义 | 标准 JSON Schema |
| 并行调用 | 需要框架支持 | 原生支持 parallel tool calls |

## 面试怎么答

> Tool Calling 和 Function Calling 的关系，我理解是父子关系：工具调用是目的，函数调用是一种实现方式。传统做法是通过 Prompt 让模型输出特定格式的文本，框架再解析——这是最早的工具调用形态，灵活但不稳定。Function Calling 是 OpenAI 从 GPT-3.5-turbo-0613 开始原生支持的机制，Anthropic 叫 Tool Use，本质一样：模型不把工具调用混在文本里，而是通过独立的结构化字段输出，框架侧解析和执行都更可靠。
> 
> 工作流程是：把工具定义（JSON Schema）随请求发给模型 → 模型决定是否调用、输出结构化调用意图 → 框架执行工具拿到结果 → 把结果追加回对话 → 模型继续推理直到给出最终答案。这个循环可能跑多轮，直到 stop\_reason 是 end\_turn 而不是 tool\_use。
> 
> 面试里容易被问到的细节：description 字段写得好不好直接影响模型的工具选择质量；parallel tool calls 支持一次请求里调多个工具并行执行；工具执行结果要原样追回对话，否则模型下一步缺上下文。

## 高频追问 & 加分点

-   **Q1：Function Calling 和 ReAct Prompting 怎么选？** 两者解决同一个问题，但适用场景不同。ReAct 是纯 Prompt 方式，任何模型都能用，灵活但解析不稳定；Function Calling 需要模型原生支持，但更可靠、structured output 更好做后处理。现在有 API 的项目我一般直接用 Function Calling，ReAct 更多见于研究论文或低端模型兜底。

-   **Q2：一次可以调用多个工具吗？** 可以。OpenAI 和 Anthropic 都支持 parallel tool calls——模型在一次响应里可以输出多个工具调用意图，框架并行执行后把所有结果一起追回去。这对需要同时查多个信息的场景效率提升明显。

-   **Q3：工具调用失败了怎么处理？** 把错误信息作为 tool\_result 返回给模型，让模型决定是重试、换参数还是放弃。不要在框架层吞掉错误——模型看不到错误就无法做出合理判断。

-   **Q4：tool description 怎么写才好？** 三个要点：①说清楚工具做什么、不做什么（边界很重要）；②说明什么情况下应该调用；③参数里每个字段都要说明格式和约束。description 是模型唯一能参考的"工具说明书"，写模糊了模型就乱调。

-   **Q5：如何防止模型过度调用工具？** 除了 description 写清楚以外，可以加系统 Prompt 说明"非必要不调工具"；或者在工具数量很多时用工具分组、动态注入（不是所有工具一次全给），减少模型的选择干扰。
