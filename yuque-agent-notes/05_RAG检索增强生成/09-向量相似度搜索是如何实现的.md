# 9. 向量相似度搜索是如何实现的？

## 知识点讲解

### 1. 核心概念

向量相似度搜索（Similarity Search / Nearest Neighbor Search）解决的问题是：在数百万个高维向量中，快速找到和查询向量最相似的 K 个——也就是 **k-NN（k-Nearest Neighbors）**。

精确的 k-NN 是 O(n×d) 复杂度（n 是向量数，d 是维度），百万数据 + 1536 维跑下来要几秒，RAG 里不可接受。实践中用的是 **ANN（Approximate Nearest Neighbor，近似最近邻）**——牺牲一点精度，换百倍以上的速度，通常 Recall@K 能保持在 95% 以上。

### 2. 技术细节

#### 2.1 距离度量

搜索前先确定"相似"的定义：

| 度量 | 公式 | 特点 |
| --- | --- | --- |
| 余弦相似度 | (A·B) / (‖A‖×‖B‖) | 最常用，衡量方向不看长度，值域 [-1,1] |
| 欧氏距离 L2 | √Σ(Aᵢ-Bᵢ)² | 几何距离，向量归一化后和余弦等价 |
| 内积（IP） | A·B | 速度最快，依赖向量长度，需要归一化 |

RAG 场景用余弦相似度或内积（向量归一化后两者等价）。

#### 2.2 三种主流 ANN 算法

**① Flat（精确搜索）**

没有索引，每次查询遍历全库。O(n) 复杂度，数据量 <10 万可以接受，更大就不行了。通常只用来做 ANN 精度的参照基准。

**② IVF（Inverted File Index）**

思路：先聚类，搜索时只在最近的几个簇里找。

-   离线：K-Means 把向量聚成 nlist 个簇，存每个簇的倒排列表

-   在线：找最近的 nprobe 个簇，在这些簇里精确搜索

nprobe 越大，精度越接近 Flat，速度越慢。通常设 nprobe = nlist 的 5-10%。

**③ HNSW（Hierarchical Navigable Small World）**

目前最流行的 ANN 算法。把所有向量组织成多层图：

-   底层（layer 0）包含所有向量，密集连接

-   上层是下层的采样子集，稀疏连接（"快速通道"）

-   插入和搜索都从顶层开始，逐层向下精化

时间复杂度约 O(log n)，精度高（95-99%），无需离线训练，支持动态插入。是大多数向量数据库的默认索引。

关键参数：M（每个节点的最大连接数，越大精度越高但内存越多，推荐 16-32）；ef\_construction（构建时的搜索宽度，越大质量越好但构建越慢，推荐 100-200）；ef\_search（查询时的候选集大小，越大精度越高但越慢，推荐 64-128）。

#### 2.3 精度与速度的权衡

生产里通常找到"95% Recall + 可接受延迟"的甜蜜点就够了。

## 面试怎么答

> 向量相似度搜索的核心问题是：O(n) 精确搜索在大规模数据下太慢，需要用 ANN 换速度。三种主流算法：Flat（精确，只适合 <10 万的小数据集）；IVF（先聚类再在簇内搜索，适合超大规模，nprobe 参数控制精度/速度权衡）；HNSW（分层图结构，O(log n) 复杂度，精度高，无需离线训练，是目前最常用的）。
> 
> 距离度量上，RAG 场景最常用余弦相似度。向量归一化后，内积运算等价于余弦相似度，而且内积更快——所以实践中通常归一化存储、用内积检索。
> 
> HNSW 有三个关键参数：M（节点连接数，越大精度越高但内存越多，推荐 16-32）；ef\_construction（构建时搜索宽度，影响索引质量，推荐 100-200）；ef\_search（查询时候选集大小，越大精度越高，可以在线调整，推荐 64-128）。调参的指导原则是：在目标 Recall@K（通常 95%）前提下，最大化 QPS。

## 高频追问 & 加分点

-   **Q1：HNSW 和 IVF 各自什么时候用？** HNSW 是默认首选——精度高、无需训练、支持动态插入，大多数场景够用。IVF 的优势是内存占用低（特别是 IVF+PQ 组合），适合内存受限但数据量极大（十亿级）的场景。数据量 <1 亿 → HNSW；数据量 >1 亿且内存紧张 → IVF。

-   **Q2：ef\_search 怎么调才合理？** 先在测试集上建一条 Recall@K vs 延迟的 Pareto 曲线，找到"够用的精度（如 95%）对应的最小 ef\_search"。生产里可以根据请求优先级动态调：普通用户查询用低 ef\_search（快），重要或离线任务用高 ef\_search（准）。

-   **Q3：向量更新（插入/删除）对 HNSW 精度有影响吗？** 插入没问题，HNSW 支持动态增量插入。删除有问题——HNSW 只能软删除（标记不返回），不能真正从图结构里移除，长期大量删除会影响精度。解决方案：定期重建索引，或者用 Qdrant/Weaviate 这类内部实现了 compact 机制的向量库。

-   **Q4：多向量搜索（ColBERT 风格）是什么？** ColBERT 不是用一个向量表示整个文档，而是给文档的每个 token 都生成一个向量，查询时用 MaxSim（每个查询 token 和所有文档 token 取最大相似度，再求和）做更细粒度的匹配。精度更高，但存储和计算成本也更高。适合对精度要求极高的场景。

-   **Q5：GPU 加速向量搜索是怎么工作的？** GPU 有大量并行计算单元，特别适合向量点积的批量计算。Faiss 支持 GPU 版本，在 GPU 上做 Flat 搜索（精确搜索）的速度可以媲美 CPU 上的 HNSW，适合小批量高频查询的场景。不过 GPU 内存有限，向量数量受限，通常用于实时性要求极高的场景。
