# 10. 如何设计高质量的 Prompt 模板？

## 知识点讲解

### 1. 核心概念

Prompt 模板是把 prompt 里的固定部分和可变部分分离的工程实践。固定部分（角色定义、格式约束、示例）写进模板；可变部分（用户输入、具体数据）用占位符表示，运行时填入。

好处很直接：可以复用、方便维护、容易迭代、降低每次写 prompt 的认知成本。

高质量的模板不只是"把指令写进去"，而是经过测试、有版本管理、能处理边界情况的可靠组件。

#### 2.2 占位符设计原则

-   命名语义清晰（{user\_question} 比 {q} 好）

-   为每个占位符写说明文档（类型、示例、限制）

-   区分必填和可选占位符

-   考虑占位符内容可能影响 prompt 解析的边缘情况（比如用户输入里有 {}）

#### 2.3 模板版本管理

模板改动要留版本记录，不然：

-   不知道哪个版本效果好

-   出了问题无法回滚

-   多人协作容易冲突

## 面试怎么答

> Prompt 模板是把固定部分（角色、约束、示例）和可变部分（用户输入）分离的工程实践。高质量的模板有几个要素：结构清晰（角色 → 任务 → 约束 → 示例 → 占位符 → 格式）、占位符命名语义化、有边界处理（告诉模型无法完成时怎么办）、有版本管理。
> 
> 模板的核心价值是可复用和可维护。把 prompt 逻辑集中在模板里，而不是散落在代码各处，改一处就全部生效，也方便做 A/B 测试和效果追踪。
> 
> 工程上我自己习惯把模板当代码对待——用 git 管版本、有 changelog、每次改动都跑测试集对比，不靠主观感觉判断好坏。

## 高频追问 & 加分点

-   **Q1：模板里的示例应该怎么选？** 选最能覆盖"边界情况"的示例：典型正常输入、边界情况（空值、极端值）、可能让模型困惑的歧义输入。不要只选最简单的"理想情况"示例——那种模型本来就会处理，加了也没太大帮助。

-   **Q2：如何做模板的 A/B 测试？** 固定测试集（100-200 条有标注的样本），两个版本的模板各跑一遍，用量化指标（格式合规率、评分准确率）对比。关键是测试集要有代表性，不能只测"理想输入"。

-   **Q3：Prompt Caching 和模板有什么关系？** Prompt Caching（Anthropic、OpenAI 都支持）会把 prompt 固定部分（System Prompt、Few-shot 示例）的 KV-Cache 缓存在服务端。模板里的固定部分越长、越稳定，Caching 命中率越高，成本越低。这也是把固定内容集中在模板固定部分的另一个理由。

-   **Q4：不同场景的模板应该完全独立还是有继承关系？** 视规模而定。规模小：独立模板就够了，简单清晰。规模大（几十上百个模板）：可以设计基础模板（base template），包含通用角色和约束，特化模板继承并扩展。但不要过度工程化——模板系统本身的复杂度应该远小于它解决的问题。
