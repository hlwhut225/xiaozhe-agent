# 9. Agent 成本过高如何优化

## 知识点讲解

### 1. 核心概念

Agent 成本优化的核心思路：**找到成本热点，有针对性地降，而不是全面压缩质量**。

Agent 的成本构成通常是：LLM API 调用（70-80%）、工具调用（10-15%）、存储和计算（5-10%）。优化要从 LLM 调用着手。

降低 LLM 成本有三个方向：

1.  **减少调用次数**（缓存 + 合并请求）

1.  **降低单次 Token 消耗**（压缩 prompt + 控制输出长度）

1.  **换更便宜的模型**（小任务不用大模型）

### 2. 技术细节

#### 2.1 成本分析先行

不做分析就优化，容易把精力花在没价值的地方。先量化：

-   统计各类任务的 Token 消耗分布（P50、P95、P99）

-   找出调用频次最高的任务类型

-   识别"高 Token 消耗但质量差"的场景——这才是优先优化的靶点

#### 2.2 四种优化策略

**模型分级路由**：根据任务复杂度选模型。

实践中，60-70% 的任务可以用小模型处理，成本下降幅度很显著。

**语义缓存**：精确哈希匹配命中率低，用向量相似度做模糊匹配：相似度 > 0.95 的问题，直接返回缓存结果。高频重复查询的场景，缓存能减少 30-60% 的 API 调用。

**Prompt 压缩**：移除冗余描述、合并相似规则、Few-shot 示例从 5 个减到 2 个（效果差不多但 Token 少一半）。System Prompt 开启 Prompt Caching，固定部分只算一次。

**批处理**：把多个独立的小任务合并成一次调用，减少 API 往返次数。适合非实时场景（离线分析、批量处理）。

#### 2.3 质量底线

优化不能无限，要设质量底线：

-   任务成功率不低于基线的 5%

-   P99 延迟不超过 SLA 上限

-   关键任务（高风险操作）不降级到小模型

## 面试怎么答

> Agent 成本优化要从分析开始，不是盲目压缩。先看成本分布：哪类任务 Token 消耗最多、哪类任务调用频率最高、哪类任务成本高但效果差——这才是优化的靶点。
> 
> 三个最有效的手段：① 模型分级路由，简单任务（分类、抽取）用小模型，贵 3-10 倍的大模型只用在真正需要的地方；② 语义缓存，相似问题不重复调用，高频场景能减少 30-60% 调用；③ Prompt Caching（Anthropic/OpenAI 都支持），把稳定的 System Prompt 和 Few-shot 示例缓存在服务端，每次只发变化的部分，成本能降 60-80%。
> 
> 优化要设质量底线，不能无限压。每次优化后跑测试集，确认成功率没有明显下降。

## 高频追问 & 加分点

-   **Q1：缓存命中率太低怎么办？** 精确哈希匹配命中率通常不高，因为同样意思的问题表达方式千变万化。升级到语义缓存：把历史问题向量化存入向量库，新问题来了先做向量检索，相似度 > 0.95 的直接返回缓存。代价是多一次向量检索，但节省的 LLM 调用成本远大于检索成本。

-   **Q2：换小模型后质量变差怎么处理？** 不是所有任务都适合降级。先做实验：用小模型跑测试集，计算成功率对比。成功率下降 > 5% 的任务类型，不降级。只对成功率损失可接受的任务做降级。另一个方向是"小模型 + 更精细的 prompt"——小模型需要更明确的指令，可以弥补一部分能力差距。

-   **Q3：Prompt Caching 怎么用？** Anthropic 的实现：在 System Prompt 或 Few-shot 示例后加 cache\_control: {"type": "ephemeral"} 标记。第一次调用计算并缓存，后续命中缓存的部分只按缓存 Token 价格计费（约原价的 10%）。关键是缓存内容要稳定——System Prompt 要放在最前面，动态内容（用户输入）放后面，不能混在一起。

-   **Q4：成本和延迟有没有矛盾？** 有。缓存降成本但缓存查询有延迟；批处理降成本但增加等待时间；小模型省成本但可能需要更多轮推理。要根据场景优先级：实时场景优先延迟，离线批处理场景优先成本。两者都想要就需要在系统架构层面分流——实时请求走快路径，低优先级请求进批处理队列。
