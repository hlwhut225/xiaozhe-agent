# 2. 如何设计一个 AI 助理产品？

## 知识点讲解

### 1. 核心概念

AI 助理和 Agent 的核心区别在于**交互方式**：Agent 强调自主执行任务，尽量少打扰人；Assistant 强调和用户一起完成任务，用户全程可以介入和修正。

设计 AI 助理产品，绕不开一个词：**信任**。用户愿不愿意长期用，取决于他信不信这个产品——信它的能力、信它的安全、信它不会乱来。

产品层面，四个核心设计原则：

-   **响应性**：用户体感不能卡，首 token 延迟目标 <500ms，超过 1s 要给进度反馈

-   **可预测性**：相似问题输出不能差太多，让用户建立预期

-   **学习性**：能记住用户的偏好、历史、常用信息

-   **可控性**：用户随时能打断、修正、重试，不能让用户感觉系统在"失控"

### 2. 技术细节

#### 2.1 能力分层

AI 助理的能力可以按成本和风险分四层，从下往上叠加：

| 层级 | 能力 | Token 成本 | 业务风险 |
| --- | --- | --- | --- |
| 基础层 | 文本生成、FAQ 问答 | 低 | 低 |
| 增强层 | RAG 知识库集成、个性化召回 | 中 | 低 |
| 智能层 | 工具调用、流程自动化 | 高 | 中 |
| 自主层 | 完整 Agent、多步骤自动执行 | 很高 | 高 |

实际产品不需要一上来就做到第四层。把基础层做稳、增强层做准，80% 场景就能覆盖了。

#### 2.2 关键体验指标

| 指标 | 含义 | 目标值 |
| --- | --- | --- |
| TTFT（首 token 延迟） | 用户提问到看见第一个字的时间 | <500ms |
| 端到端延迟 | 完整回答生成时间 | 根据内容长度，P95 <8s |
| 自助解决率 | 不需要转人工就解决的比例 | >70% |
| 用户满意度（CSAT） | 对话后用户主动评分 | >80% |
| 留存率 | 7 日/30 日回来再用的比例 | 核心产品指标 |

#### 2.3 记忆系统设计

AI 助理要"记住"用户，有四类记忆要处理：

1.  **短期记忆（Session Memory）**：当前对话上下文，放在 LLM context window 里，对话结束就清

1.  **长期记忆（Long-term Memory）**：用户的偏好、历史结论、常用信息，存向量库 + 摘要

1.  **工作记忆（Working Memory）**：当前任务的中间状态，Redis 短存

1.  **外部记忆（External Memory）**：用户连接的知识库、文档，RAG 检索

长期记忆的挑战是**写入时机**：不能每轮对话都写，信噪比会很低。我一般的策略是：对话结束时由 LLM 提取 2-3 条"值得记住的事实"，打分后写入。

## 面试怎么答

> AI 助理产品设计的核心词只有一个：**信任**。用户信任助理的能力才会长期用，信任数据安全才会敢于分享个人信息，信任系统稳定才不会被一次超时吓跑。所有设计决策都绕这个词转。
> 
> 体验上三个必须做好的：**流式输出**（首 token 延迟要控制在 500ms 内，用户感知很敏感）、**记忆管理**（短期记忆放上下文窗口，长期记忆用向量库+LLM 提取，两层分开）、**可中断可修正**（用户随时能打断、重新表述，系统不能卡着等）。
> 
> 成本方面，我一般做两层控制：单个请求的 token 预算检查（跑之前估算）+ 用户每日 quota（跑完记账）。缺一个都会被刷。流式输出同时做成本实时累计，快要超预算时提前告警或截断，不能等跑完再算。
> 
> 记忆系统容易踩的坑是写太多——每轮都提取、什么都存，很快噪声就会盖过有效信息。我的策略是对话结束时才触发提取，LLM 只提取 1-3 条"明确的用户背景信息"，打低分的就丢弃。

## 高频追问 & 加分点

-   **Q1：首 token 延迟怎么压到 500ms 以内？** 两条路：一是用更快的模型（在质量和速度之间取平衡），二是做 prompt 缓存（把 system prompt 前缀缓存在 LLM 侧，Anthropic 的 prompt caching 命中率到 60%+ 时效果很显著）。另外，用户打字过程中可以提前做 RAG 检索，等用户按发送时上下文已经准备好了。

-   **Q2：用户的个性化偏好怎么学习？** 分显式和隐式两种。显式：用户直接告诉你的偏好（"我喜欢简短回答"）直接存。隐式：从用户行为推断——用户反复点"重新生成"说明不满意，点"有帮助"说明满意，这些信号都可以用来调整输出风格。别太激进，慢慢迭代。

-   **Q3：如何处理敏感数据和隐私？** 原则是**最小化采集**：只存完成功能必须的数据，不要图方便什么都存。存储加密，传输用 HTTPS/TLS。让用户可以查看、导出、删除自己的数据，这是合规的底线，也是建立信任的基础。

-   **Q4：AI 助理 vs 搜索引擎，设计上有什么核心差别？** 搜索引擎返回文档列表，用户自己综合；助理直接给答案，用户期望的是"帮我想好了"。这意味着助理对准确性的要求更高（用户不会自己再核实），对个性化的要求更强（相同问题不同人可能需要不同深度的答案）。设计评估指标时要把"准确性"和"适配性"都纳入，不能只看用户满意度。

-   **Q5：产品冷启动阶段记忆系统怎么做？** 新用户没有历史数据，长期记忆是空的。冷启动可以做两件事：一是在引导流程里问几个关键问题（职业、使用场景、偏好风格），显式初始化用户档案；二是用行业通用的偏好模板兜底，等积累足够数据后再用个性化的覆盖。
