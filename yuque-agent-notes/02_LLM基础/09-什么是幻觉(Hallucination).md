# 9. 什么是幻觉(Hallucination)?

## 知识点讲解

### 1. 核心概念

幻觉（Hallucination）是指 LLM 生成的内容看起来合理流畅，但实际上是虚构的或者错误的。可能是编造的事实、不存在的引用、错误的数字，也可能是自相矛盾的推理。

幻觉不是 bug，而是 LLM 机制的内在产物。模型做的是"概率上最可能的下一个 Token"，不是"事实上最正确的信息"——这两件事在大多数情况下是一致的，但不总是。

这是目前 LLM 应用里最核心的工程风险之一，尤其在医疗、法律、金融等高风险场景，幻觉可能造成严重后果。

### 2. 技术细节

#### 2.1 幻觉的分类

| 类型 | 描述 | 示例 |
| --- | --- | --- |
| 事实幻觉 | 编造不存在的事实 | 虚构的历史事件、错误的科学数据 |
| 引用幻觉 | 引用不存在的文献或人物 | 假的论文标题、虚构的引语 |
| 逻辑幻觉 | 推理过程有误 | 计算错误、违反已知前提 |
| 一致性幻觉 | 在同一对话里自相矛盾 | 前文说 A 后文说非 A |
| 知识截止幻觉 | 对知识截止后的信息编造 | 捏造最新事件或新产品数据 |

#### 2.2 为什么会幻觉

从机制层面：

1.  **概率本质**：模型优化的是 Token 预测概率，不是事实正确性。"听起来合理"和"事实正确"不等价。

1.  **知识存储的不精确性**：知识以分布式方式编码在参数里，对训练频率低的冷知识，"记忆"本来就不准确。

1.  **训练数据的质量问题**：互联网文本里本来就有大量错误信息，模型学进去了。

1.  **采样的随机性**：即使 Temperature 设 0，浮点不确定性也可能带来极少数偏差。

1.  **过度自信的表达风格**：RLHF 训练让模型倾向于给出确信的回答，但确信的语气和内容正确是两回事。

#### 2.3 幻觉的严重性与场景关系

风险从低到高排序大致是：**创意写作 < 通用对话 < 代码 < 技术文档 < 医疗/法律/金融**

创意写作允许一定虚构；代码里的幻觉会让程序跑不起来；医疗建议的幻觉可能伤人。不同场景对幻觉的容忍度差异极大。

## 面试怎么答

> 幻觉是 LLM 生成看起来合理但实际错误的内容。它不是偶然 bug，而是机制的内在特性——模型优化的是"下一个 Token 的概率"，不是"事实是否正确"，两件事不总是一致的。
> 
> 幻觉可以分几类：事实幻觉（编造不存在的信息）、引用幻觉（虚构文献）、逻辑幻觉（推理出错）、一致性幻觉（自相矛盾）。产生原因包括：知识在参数里存储不精确、训练数据本来就有噪声、RLHF 让模型倾向于给出"自信的"回答。
> 
> 工程上减少幻觉的主要手段：RAG（检索增强，把知识放外部数据库而不是依赖参数记忆）、指令约束（明确告诉模型"不知道就说不知道"）、低温采样（减少随机性）、自我验证（让另一个 LLM 做 fact-check）。完全消除幻觉目前做不到，工程上的目标是"可检测 + 可降低到业务可接受的水平"。

## 高频追问 & 加分点

-   **Q1：RAG 能彻底解决幻觉吗？** 不能。RAG 主要解决知识来源的问题（让模型有可靠的文档参考），但如果检索到的文档本身是错的，或者模型在生成时偏离了文档，还是会幻觉。而且模型有时候会"半忽略"文档，在文档之外编造内容。需要在 prompt 里明确强调"只基于文档回答"，并加 citation 验证。

-   **Q2：怎么评估一个模型的幻觉程度？** 常见的评估集有 TruthfulQA（专门测幻觉）、HaluEval、FActScore（文章级别的事实准确性）。工程里可以用 LLM-as-judge：用另一个强模型逐句检查事实，计算幻觉率。人工评估准确但贵，通常抽样做。

-   **Q3：模型大了幻觉会减少吗？** 有一定关系但不是线性的。更大的模型记住了更多知识，对常见话题幻觉确实少些；但对冷知识、新信息、超出训练分布的问题，大模型一样会幻觉，甚至因为回答更自信而更危险。模型大小解决不了根本问题。

-   **Q4：怎么让模型主动表达不确定性？** 两个方法：① Prompt 层面：加"如果不确定，请明确说出你的把握程度"；② Fine-tune 层面：在数据里加入大量"我不确定"、"这超出了我的知识范围"这类样本，让模型学会表达不确定。Anthropic 的 Constitutional AI 方法里就包含了这一点。
