# 2. LLM 是如何训练的?

## 知识点讲解

### 1. 核心概念

LLM 的训练分三个阶段，各阶段目标完全不同：

1.  **预训练**：在海量无标签文本上用自监督学习，让模型学语言的基本规律和世界知识。最烧钱的一步。

1.  **监督微调（SFT）**：在{指令 → 理想回答}对上训练，把"补全机器"变成"任务执行器"。

1.  **RLHF**：用人类偏好数据训练奖励模型，再用 PPO 让 LLM 生成更符合人类期望的输出。

三个阶段缺一不可。只有预训练的模型会帮你"续写句子"，不会听指令；只有 SFT 没有 RLHF 的模型，质量边界和安全性都不够好。

### 2. 技术细节

#### 2.1 预训练

训练目标极简单：给定前 N 个 Token，预测第 N+1 个，用交叉熵损失。整个互联网的文本都是"免费的标签"——这就是自监督学习的魔法。

规模上的数字感知：

| 项目 | 量级 |
| --- | --- |
| 训练数据 | 数 TB，几万亿 Token |
| 参数量 | 7B～1T |
| 训练时间 | 数周～数月 |
| 训练成本 | 百万～亿美元 |

#### 2.2 监督微调（SFT）

数据少但质量要求高。通常 5K～100K 条高质量指令-回答对就能让模型"会说话"。

关键细节：训练时只在回答部分计算 loss，指令部分不算——这样模型学的是"怎么回答"，而不是"怎么复述指令"。

#### 2.3 RLHF

两步走：

**第一步：训练奖励模型（Reward Model）** 给模型看同一个问题的两个不同回答，让人类标注"哪个更好"，用这些偏好对训练奖励模型，让它学会给回答打分。

**第二步：PPO 策略优化** LLM 生成回答 → 奖励模型打分 → PPO 更新 LLM 参数，最大化预期奖励，同时用 KL 散度约束，防止偏离 SFT 基础模型太远。

| 阶段 | 数据类型 | 数量 | 主要目标 |
| --- | --- | --- | --- |
| 预训练 | 无标签文本 | TB 级 | 学语言和知识 |
| SFT | 指令-回答对 | 5K-100K | 学指令遵循 |
| 奖励模型 | 偏好对 | 数万 | 学质量评估 |
| PPO | 采样 + 奖励 | 动态 | 优化输出质量 |

#### 2.4 RLHF 的替代方案

PPO 实现复杂、训练不稳定，业界出现了更简单的替代：

-   **DPO（Direct Preference Optimization）**：直接在偏好数据上优化 LLM，跳过单独训练奖励模型的步骤，实现更简单、结果相当。

-   **RLAIF**：用另一个 LLM（比如 Claude）代替人类做偏好标注，大幅降低标注成本。

## 面试怎么答

> LLM 训练分三阶段。预训练是重头戏——在海量文本上做 next-token prediction，数据是自监督的不需要标注，但算力成本极高。预训练后模型能"补全文字"，但不会"听指令"。
> 
> 第二步 SFT，在高质量的指令-回答对上微调，让模型学会遵循自然语言指令。关键细节是 loss 只算在回答部分，不算指令部分。
> 
> 第三步 RLHF：先用人类偏好数据训练一个奖励模型，再用 PPO 让 LLM 朝着"奖励模型打高分"的方向优化，同时加 KL 散度约束防止偏得太远。现在更流行的做法是 DPO——直接在偏好数据上优化 LLM，跳掉奖励模型这一步，实现更简单、效果相当。

## 高频追问 & 加分点

-   **Q1：三个阶段为什么缺一不可？** 没有预训练，模型没有世界知识；没有 SFT，模型不会听指令；没有 RLHF，输出质量和安全性不达标。每个阶段解决的问题不同，缺哪个都有明显短板。

-   **Q2：DPO 比 RLHF 好在哪？** DPO 省掉了单独训练奖励模型的步骤，实现更简单，训练更稳定，成本更低。实验结果表明效果和 PPO 相当甚至更好。业界现在用 DPO 的越来越多。

-   **Q3：SFT 数据量要多少？** 质量远比数量重要。高质量的 5K 对可能比低质量的 100K 对效果更好。开源的 Alpaca 数据集（5.2 万条）、LIMA 数据集（1000 条高质量数据）都印证了这一点。

-   **Q4：预训练数据质量怎么保证？** 通常三步：去重（近似重复的文本大量删掉）、质量过滤（用分类器去掉低质量内容）、有害内容过滤。数据工程现在被认为和模型架构一样重要。

-   **Q5：RLHF 还有什么缺点？** 奖励 hacking——PPO 可能找到让奖励模型打高分但实际质量差的策略（比如说废话把回答拉长）。解决方法是 KL 约束加强，或者持续迭代奖励模型。完全对齐人类价值观目前仍是开放问题。
