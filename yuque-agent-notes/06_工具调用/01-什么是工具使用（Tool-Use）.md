# 1. 什么是工具使用（Tool Use）？

## 知识点讲解

### 1. 核心概念

Tool Use，说白了就是给 LLM 装上"手"。

模型本身只能生成文本，它知道北京可能下雨、知道 Python 的语法，但它查不了实时天气、跑不了你的 SQL。Tool Use 就是打通这个边界的机制：LLM 生成一段"我要调用哪个工具、传什么参数"的结构化输出，Agent 框架解析它、执行工具、把结果塞回去，让模型继续推理。

这个闭环一转，Agent 就能做到"我现在去查一下，然后告诉你"，而不只是"根据我的训练数据，大概是这样"。

工具按性质可以分几类：

| 类型 | 示例 | 核心价值 |
| --- | --- | --- |
| 读信息 | 搜索引擎、天气 API、数据库查询 | 突破训练数据的时效限制 |
| 写操作 | 发邮件、创建文件、写数据库 | 真正改变外部世界状态 |
| 计算 | 代码执行、计算器 | 精确计算，不靠模型"估算" |
| 系统集成 | Slack、GitHub、日历 | 接入已有业务系统 |

## 面试怎么答

> Tool Use 就是让 LLM 从"只能说"变成"能做"的机制。模型生成一段结构化的工具调用，Agent 框架解析、执行、把结果塞回去，模型继续推理，这个循环走下去直到任务完成。
> 
> 技术上，每个工具都有一份 Schema，描述名称、用途、参数。LLM 读 Schema 来决定该不该调、怎么调。Anthropic 和 OpenAI 的格式稍有区别，Anthropic 叫 Tool Use，字段是 input\_schema；OpenAI 叫 Function Calling，字段是 parameters，但原理一样。
> 
> Tool Use 能做什么？突破训练数据的时效性（查实时数据）、突破文本的计算限制（执行代码）、实际改变系统状态（发邮件、写数据库）。这三件事纯 LLM 都做不到，有了 Tool Use 就都能做了。
> 
> 面试里容易被追问：一次调用可以带多个工具结果吗？可以，把多个 tool\_result 一起返回就行。工具调用失败怎么处理？在结果里标明错误，让模型自己决定重试还是换思路。

## 高频追问 & 加分点

-   **Q1：Tool Use 和 Agentic Loop 是什么关系？** Tool Use 是单次"调用工具"的能力，Agentic Loop 是把多次 Tool Use 串成闭环的控制流。有 Tool Use 不一定有 Agent，但 Agent 一定用 Tool Use 驱动——关键看有没有多步迭代和动态决策。

-   **Q2：LLM 是怎么决定要不要调工具的？** 本质是 token 概率问题。给定用户请求和工具 Schema，LLM 在生成时选择输出"工具调用"还是"普通文本"。描述越清晰、使用场景越具体，模型的判断越准确。few-shot 示例也有帮助。

-   **Q3：工具结果很长怎么办，会撑爆 context 吗？** 会的，这是实际工程里很常见的问题。处理方式：截断（只取前 N 个字符或 topK 结果）、摘要（用另一次 LLM 调用压缩结果）、分页（先拿第一页，按需再取）。

-   **Q4：并行工具调用怎么处理？** Claude 和 GPT-4 都支持一次响应里包含多个工具调用。处理方式是把所有调用的结果收集齐，放在同一个 user 消息里一次性返回，不需要每个工具单独一轮。

-   **Q5：Tool Use 有没有安全风险？** 有，而且是工程重点。风险点：LLM 被诱导调用越权工具（prompt injection）、参数被篡改（传危险 SQL/命令）、写操作被误触发。防御手段：参数白名单验证、危险操作二次确认、审计日志、工具粒度最小化。
